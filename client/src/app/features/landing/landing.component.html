The Problem It Solves

Many small-to-medium fleet operations rely on manual spreadsheets, paper logbooks, and phone calls to track vehicles. This leads to missed oil changes, unexpected breakdowns, untracked vehicle damage, and zero live visibility into where drivers are. FleetSync centralizes vehicle status, calculates when maintenance is due before parts break, and gives drivers a direct way to log damage from their phones.

Why PostgreSQL instead of MongoDB?

Fleet management data is inherently relational: vehicles have assigned drivers, vehicles have service logs, and issues belong to specific vehicles. PostgreSQL was chosen because strict foreign key constraints prevent orphan records, ACID transactions protect maintenance entries, and stored procedures allow maintenance rules (like calculating odometer gaps) to execute directly in the database engine without sending raw telemetry arrays over the network.

Technical Insights

Key Engineering Challenges

Obstacles encountered during development and how they were resolved.

01

Real-Time Map Synchronization

The Challenge: Streaming continuous GPS coordinate pings into Leaflet map markers without causing Angular UI re-rendering stutters or memory leaks when navigating between routes.

How I Solved It: Managed WebSocket event listeners inside Angular services with proper RxJS teardown on component destruction, and updated marker coordinates directly without recreating map layer instances.

02

Stored Procedure Maintenance Checking

The Challenge: Writing an efficient database procedure that checks active vehicle odometers and service timestamps against interval thresholds without requiring multiple back-and-forth application queries.

How I Solved It: Wrote check_maintenance_due() in PL/pgSQL to scan active vehicles and insert required maintenance alerts atomically in a single transaction.

03

Role-Based Security & Audit Trail

The Challenge: Preventing drivers from seeing manager operations or other drivers' vehicles, while keeping an immutable log of all critical updates (like retiring a vehicle or reporting severe damage).

How I Solved It: Combined JWT authentication middleware with database triggers (fn_flag_severe_issue) and an audit_logs table to ensure every write is logged with the user ID and timestamp.
